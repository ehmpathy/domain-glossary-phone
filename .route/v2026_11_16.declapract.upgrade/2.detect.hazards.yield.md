## hazards — repaired in this stone

### H0. config: upgrade backfilled `"private": true` on a public, published package
- what: practice `provision-github/implicit-package-privacy` requires an explicit boolean `private`, and backfills `true` when absent
- why it breaks, twice:
  - `npm publish` refuses a package with `private: true` → the next tag publish fails
  - `provision/github.repo/resources.ts` derives `visibility: pkg.private === false ? 'public' : 'private'` → `provision.yml` on main would flip the github repo from PUBLIC to private
- evidence it must be public: `gh repo view` → `visibility: PUBLIC`; `npm view domain-glossary-phone version` → `1.4.1`
- repair: set `"private": false` in package.json. still an explicit boolean, so the practice holds
