## defect inventory

### D1. `test:lint` failed — depcheck: unused devDependency `ts-node`
- what: `depcheck` exits non-zero with `Unused devDependencies * ts-node`, so `test:lint` fails
- how: `git diff origin/main -- package.json jest.*.config.ts`
  - before: jest configs used `ts-jest` transform; `ts-node` let jest load the `.ts` config files
  - after: transform is `@swc/jest`, and each config opens with `@jest-config-loader esbuild-register`
- why: the practice swapped the `.ts` config loader to `esbuild-register` but left the prior `ts-node` devDependency in place. depcheck now finds no import of it
- fix: `pnpm remove ts-node`. lint passes; unit still loads `jest.unit.config.ts` through `esbuild-register`
  - lockfile: `pnpm-lock.yaml` `importers` no longer lists `ts-node`, so package.json and lock agree for a frozen install. `ts-node` stays in the lock only as an optional peer of `jest-config@30` (`pnpm why ts-node` → `jest-config@30.2.0`), which depcheck does not count

### D2. package marked private — would block npm publish and flip the github repo private; repaired in stone 2 (H0), recorded here for the inventory
- what: upgrade backfilled `"private": true` on a public, published package
- how: `git diff origin/main -- package.json` → `+ "private": true`; main had no `private` key
- why: practice `implicit-package-privacy` demands an explicit boolean and fails closed to `true` when the key is absent. `npm publish` refuses a private package, and `provision/github.repo/resources.ts` maps `private !== false` → `visibility: 'private'`
- fix: `"private": false` (repo is public; package published at 1.4.1). no gate tests this; it would have surfaced only at tag publish and at `provision` apply
