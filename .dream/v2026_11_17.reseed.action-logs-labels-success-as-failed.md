# 🌙 dream: show.gh.action.logs must not label a successful job as failed

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy (role=mechanic, skill=show.gh.action.logs)
- caught 2026-11-17

## .the cue that fired

`rhx show.gh.action.logs --flow provision --run-id 44064561363 --scope plan --full` printed `⛈️ 1 failed job(s)` and `⛈️ github / plan`, though the jobs api reports that job and each step as `success`.

## .the gap, precisely

with `--full --scope`, the skill renders the scoped job under the failed-jobs header and glyph regardless of its conclusion. a reader concludes cicd is red when it is green. it also refused to print the log body (`terminal escape sequences`), so the header was the only output.

## .the shape of the fix

- header and glyph follow each job's `conclusion`: `⛈️` failed, `✨` success, `💤` skipped
- strip or pass through escape sequences so `--full` prints the log
- clamp: a run with one successful job, `--full --scope <it>` → no "failed" text

## .why it is not done in this round

the skill lives in another repo; this route read the jobs api directly.
