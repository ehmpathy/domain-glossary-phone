# 🌙 dream: ts-node-beside-esbuild-register must fire in repos on tests-node

- kind: reseed
- owner: ehmpathy/declapract-typescript-ehmpathy
- caught 2026-11-16

## .the cue that fired

a declapract upgrade left `ts-node` in devDependencies, so `test:lint` failed on depcheck, though a practice exists to remove it.

## .the gap, precisely

`src/practices/typescript-any/bad-practices/ts-node-beside-esbuild-register/package.json.declapract.ts`, `isTsNodeStillUsed`, lines 43–51: the filter `/^jest\..*\.ts$/` counts every root `jest.*.ts` as a config. tests-node ships six non-config root files (`jest.{unit,integration,acceptance}.env.ts`, `jest.integration.env.db.ts`, `jest.{integration,acceptance}.prepare.ts`) that never carry `@jest-config-loader`, so the check always reads "ts-node still used" and the fix never runs.

why the upstream clamp stays green: its fixture `src/.test/assets/tool-swap-removals/repo-after-swaps/` holds only `jest.unit.config.ts` — no env or prepare file. the fixture must carry the full tests-node file set. prior issue: #660 (closed) shipped this practice.

## .the shape of the fix

- narrow the filter to configs: `/^jest\.(.+\.)?config\.ts$/`
- clamp: fixture with tests-node env/prepare files + pragma'd configs + `ts-node` and `esbuild-register` declared → apply removes `ts-node`; revert the filter → clamp goes red
- prove first: `jest.*.prepare.ts` loads as `globalSetup`. jest documents that `transform` applies to it, but the consumer repo that found this bug had no test that runs globalSetup. the clamp must run a real `prepare` globalSetup with `ts-node` absent, else the narrow filter could strip `ts-node` from a repo that still needs it

## .why it is not done in this round

the practice lives in another repo; this route repairs the consumer (`pnpm remove ts-node`) and records the upstream defect.
